# 现场演示脚本

> 目标：在 3 分钟内展示"报名—签到—统计"的完整链路，其中**含一次真实签到**。其余功能按时间余量取舍。

## 一、演示前 10 分钟检查清单

- [ ] 关闭无关窗口（微信、QQ、浏览器其他标签），桌面只留演示用的 Chrome 窗口。
- [ ] 启动系统：双击 `release\CampusActivitySystem\start-demo.bat`（默认 8080，也可 `start-demo.bat 8081`）。
- [ ] 浏览器打开 `http://127.0.0.1:8080`，看到登录页即说明启动成功；若打不开，先看该窗口是否报错。
- [ ] 运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-demo.ps1`，记下输出的 `activityId`、`checkinCode`、学生账号。
  - 该脚本会临时创建一场"4 分钟后开始"的活动，否则种子活动的签到窗口尚未开启。
- [ ] 打开三个窗口（或三个标签页），分别登录：学生 `2023000201`、组织者 `2022010102`、管理员 `admin`，密码均为 `123456`。
- [ ] 投屏检查：Chrome 按 `F11` 全屏，`Ctrl+0` 复位缩放；系统缩放 125% 时，浏览器窗口建议设为 1600×900。
- [ ] 兜底：确认 `release\CampusActivitySystem.zip` 在 U 盘里，另一台电脑可直接解压运行。

## 二、3 分钟主流程

### 0:00–0:20 开场

> "系统分学生、组织者、管理员三类角色，一条主线是：活动发布、审核、报名、签到、评价、统计。下面按一个学生的实际使用顺序演示。"

### 0:20–1:00 学生：浏览与报名

1. 学生窗口 → 首页（公告 + 热门活动 + 最新发布）。
2. 点"活动中心" → 选"人工智能与校园生活专题讲座" → 详情页。
   - 指一下报名进度条（61/80）、剩余名额、质量分。
3. 点"立即报名" → 提示"报名成功" → 进度变为 62/80。

> 话术："名额扣减用的是一条带条件的 UPDATE，不是先查后改。稍后在组织者端可以看到计数和名单是一致的。"

### 1:00–1:40 学生：签到

1. 切到"我的报名" → 找到刚由脚本准备好的"演示活动" → 点"去签到"。
2. 输入签到码（脚本输出的 6 位数字）→ "签到成功"。
3. 回到活动详情 → 状态变为"已签到"，进度 +1。

> 话术："签到码 6 位，默认 30 分钟有效；未过期时重复生成会复用同一码，避免转发截图代签。签到窗口是活动开始前 30 分钟到结束。"

### 1:40–2:20 组织者：名单与统计

1. 组织者窗口 → "我的活动" → 对应活动 → "签到管理"。
   - 指签到码卡片（剩余有效时间）、签到统计（应到/已到/未签到/爽约/签到率）。
2. 点"报名名单" → 展示状态、报名时间、签到时间、签到方式，演示一次"补签"（对未签到者）。
3. 返回 → "活动数据" → 报名/签到趋势、分类环形图、TOP10 排行。

> 话术："爽约在活动结束时自动判定，累计达到 2 次限制报名 30 天；补签会把违约次数回退，留了纠错通道。"

### 2:20–2:50 管理员：审核与平台统计

1. 管理员窗口 → "活动审核" → 待审核的"社团招新嘉年华" → 点"通过"。
2. 切到"平台统计" → 用户数、活动数、报名总数、签到率、活动状态与报名状态分布。

> 话术："审核与发布分离，组织者不能审核自己的活动，管理员不发布活动，避免既当裁判又当运动员。"

### 2:50–3:00 收尾

> "以上是一条完整链路。论文里还给出了 50 并发下两种实现的对照数据：条件更新成功 10 人、拒绝 40 人，先查后改 50 人全部成功、超卖 40 人。"

## 三、1 分钟极简版（时间被压缩时）

只走三步：

1. 学生报名一个还有名额的活动（看到进度 +1）。
2. 组织者打开"签到管理"，展示签到码与统计（不现场签到）。
3. 管理员打开"平台统计"，展示总体数据。

> 备用话术："签到环节我可以直接展示已有数据：这场活动报名 5 人、已签到 1 人，签到率 20%。"

## 四、应急预案

| 情况 | 现象 | 处理 |
| --- | --- | --- |
| 端口被占用 | 启动窗口报 `Port 8080 was already in use` | `netstat -ano \| findstr :8080` 找到 PID → `taskkill /PID <pid> /F`；或直接 `start-demo.bat 8081`，浏览器改 8081 |
| 数据被改乱 | 活动状态不对、名额异常 | 关掉启动窗口后重新双击 bat：H2 内存库每次启动重建，种子数据自动恢复；再跑一次 prepare-demo |
| 签到码过期 | 提示"签到码已过期" | 组织者点"重新获取"，或用"补签"演示 |
| 签到提示未开始 | "签到尚未开始，活动开始前 30 分钟开放签到" | prepare-demo 创建的活动已临近开始；若已过结束时间，重跑脚本再生成一场 |
| 页面空白/404 | 刷新后仍空白 | 确认访问的是 `http://127.0.0.1:8080`（不是 8081），必要时重启 |
| 投屏字太小 | 页面被放大或截断 | Chrome `Ctrl+0` 复位，`F11` 全屏；系统缩放调回 100% |
| 完全断网 | 无影响 | 便携包内置 JRE 与前端静态资源，不依赖网络 |
| 演示机没装 Java | 双击 bat 闪退 | 用便携包（自带 runtime），或解压 zip 到新目录再运行 |
